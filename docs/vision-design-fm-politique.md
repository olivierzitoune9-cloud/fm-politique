# **VISION DESIGN**

## **Concevoir le véritable Football Manager politique**

---

# **1\. Le problème de design à résoudre**

Le projet n’a pas simplement besoin de « beaucoup de contenu ».

Il doit résoudre un problème de game design beaucoup plus précis :

**Comment donner au joueur une liberté politique presque illimitée sans transformer le jeu en une liste infinie de boutons, de menus et de choix scénarisés ?**

C’est le problème central.

Si on veut permettre au joueur de faire énormément de choses — créer un parti, recruter quelqu’un, convaincre un journaliste, monter une association, gagner une mairie, influencer une réforme, construire un réseau, devenir ministre, soutenir un mouvement social, créer un média, prendre le contrôle d’un parti, modifier son idéologie, négocier avec des institutions, etc. — on pourrait être tenté de créer une mécanique spécifique pour chaque possibilité.

Ce serait une erreur.

Le jeu deviendrait énorme en contenu mais pauvre en profondeur.

La solution est de faire l’inverse :

**Créer des systèmes généraux suffisamment puissants pour que les possibilités particulières émergent de leur combinaison.**

C’est là que le modèle de Football Manager devient particulièrement pertinent.

---

# **2\. La différence entre contenu et possibilités**

Il faut distinguer deux choses.

### **Beaucoup de contenu**

1000 événements écrits.

1000 personnages.

500 décisions.

300 lois.

200 crises.

Cela donne un gros jeu.

Mais pas nécessairement un jeu profond.

### **Beaucoup de possibilités**

Quelques systèmes fondamentaux permettant :

* de rencontrer une personne ;  
* de construire une relation ;  
* de créer une organisation ;  
* de modifier sa réputation ;  
* de recruter quelqu’un ;  
* de créer une coalition ;  
* d’influencer un groupe ;  
* de déclencher une réaction ;  
* de subir une réaction ;  
* de modifier une institution ;  
* de changer une politique ;  
* de faire évoluer la perception du monde.

Si ces systèmes peuvent interagir librement, leur combinaison produit une quantité de situations considérablement supérieure au nombre de mécaniques explicitement codées.

**C’est cette deuxième forme de profondeur que le projet doit rechercher.**

---

# **3\. La philosophie : « quelques règles, une infinité de situations »**

Le design devrait constamment poser cette question :

« Est-ce que cette mécanique peut être réutilisée dans de nombreux contextes ? »

Par exemple, au lieu de créer :

* « convaincre un journaliste » ;  
* « convaincre un député » ;  
* « convaincre un militant » ;  
* « convaincre un entrepreneur » ;

on peut avoir un système général :

**Interaction entre deux acteurs.**

Puis les paramètres changent :

* relation ;  
* réputation ;  
* objectifs ;  
* idéologie ;  
* ressources ;  
* personnalité ;  
* information ;  
* contexte ;  
* rapport de force.

Le même moteur d’interaction peut alors produire des centaines de situations différentes.

---

# **4\. Le joueur ne doit jamais avoir l’impression de suivre un arbre**

Le pire résultat possible serait :

événement → choix A/B/C → conséquence écrite → événement → choix A/B/C.

Même avec des milliers de branches, le joueur finira par comprendre qu’il suit un arbre.

Le design doit produire une sensation complètement différente :

**« Je fais quelque chose dans le monde. »**

La différence est fondamentale.

Dans un arbre :

le jeu me demande ce que je choisis.

Dans une simulation :

**je décide ce que je veux tenter.**

Puis le monde réagit.

---

# **5\. Le joueur doit avoir des intentions, pas seulement des objectifs**

Un système classique dirait :

Objectif : gagner l’élection.

Le système imaginé ici doit permettre quelque chose de plus ouvert :

« Je veux devenir suffisamment influent pour que ce député me considère comme incontournable. »

Ou :

« Je veux construire une organisation locale avant de me lancer dans la politique nationale. »

Ou :

« Je veux trouver les personnes les plus compétentes dans ce domaine et les réunir. »

Ou :

« Je veux faire émerger une nouvelle force politique. »

Ou simplement :

« Je veux voir si je peux transformer cette petite association en organisation nationale. »

Le joueur peut donc se donner ses propres objectifs.

---

# **6\. Les objectifs doivent être des boussoles, pas des missions**

Le jeu peut néanmoins proposer des objectifs :

* électoraux ;  
* financiers ;  
* organisationnels ;  
* médiatiques ;  
* institutionnels ;  
* personnels.

Mais ils ne doivent pas devenir une liste de quêtes.

Ils doivent plutôt servir à :

* orienter le joueur ;  
* aider son staff à prendre des décisions ;  
* déterminer quelles informations sont prioritaires ;  
* mesurer les progrès.

Par exemple :

**Objectif : construire une implantation nationale.**

Cela peut produire automatiquement :

* rapports sur les territoires faibles ;  
* recommandations de recrutement ;  
* informations sur les personnalités locales ;  
* opportunités organisationnelles.

Le joueur n’est pas obligé de suivre les recommandations.

---

# **7\. Le monde doit être plus intelligent que le joueur**

C’est une règle de design essentielle.

Le joueur doit être puissant, mais il ne doit jamais être omniscient.

Le monde doit contenir des choses qu’il ignore.

Un parti peut préparer une réunion sans qu’il le sache.

Un journaliste peut enquêter.

Un groupe interne peut discuter.

Un rival peut négocier avec une autre organisation.

Une crise peut commencer dans une région.

Un collaborateur peut changer d’avis.

Le joueur apprend ces choses lorsqu’elles deviennent accessibles à son réseau d’information.

---

# **8\. La découverte doit être une mécanique**

Le jeu ne doit pas simplement donner des informations.

Il doit donner au joueur le plaisir de **les découvrir**.

Exemple :

Le joueur constate :

« Pourquoi ce député s’oppose-t-il soudainement à notre réforme ? »

Il enquête.

Il découvre une relation.

Puis une autre.

Puis un groupe d’intérêt.

Puis une organisation locale.

Puis un financement.

Puis un ancien conflit.

Le joueur vient de produire une mini-enquête politique à partir de la simulation.

Aucun scénario spécial n’était nécessaire.

---

# **9\. Le monde doit avoir une profondeur verticale**

Chaque objet doit pouvoir être regardé à plusieurs niveaux.

Prenons un article.

### **Niveau 1**

« Le gouvernement est confronté à une nouvelle polémique. »

### **Niveau 2**

Qui l’a écrit ?

### **Niveau 3**

Quel média ?

### **Niveau 4**

Quelle audience ?

### **Niveau 5**

Quelle ligne éditoriale ?

### **Niveau 6**

Qui possède le média ?

### **Niveau 7**

Quelles relations avec les autres acteurs ?

### **Niveau 8**

Quel événement a provoqué l’article ?

### **Niveau 9**

Quel acteur a transmis l’information ?

### **Niveau 10**

Pourquoi ?

Cette profondeur verticale est essentielle.

---

# **10\. La navigation est donc une mécanique de gameplay**

Dans FM26, les développeurs expliquent que les tuiles donnent un aperçu puis s’ouvrent sur des cartes plus détaillées, tandis que le Portal sert de point d’accès aux informations et événements importants. Ils ont également renforcé la recherche pour permettre une exploration plus profonde de l’univers simulé.

Le jeu politique devrait reprendre exactement cette philosophie :

**résumé → détail → contexte → réseau → action.**

Le joueur voit quelque chose.

Il peut approfondir.

Il peut agir.

---

# **11\. L’interface doit donc être une fenêtre sur la simulation, pas un tableau de bord Excel**

Il existe un risque évident :

plus le système est complexe, plus l’interface devient monstrueuse.

Le design doit empêcher cela.

L’objectif n’est pas de montrer toutes les variables.

L’objectif est de montrer :

**les variables qui deviennent pertinentes maintenant.**

Le joueur doit pouvoir avoir une interface relativement calme dans une situation normale, puis voir émerger progressivement des informations lorsque la situation devient importante.

---

# **12\. Le principe du « contextual surfacing »**

Le jeu doit continuellement répondre à la question :

« Qu’est-ce que le joueur a besoin de savoir maintenant ? »

Pas :

« Quelles sont toutes les informations que nous possédons ? »

Si une crise économique commence à affecter un territoire, le jeu peut faire apparaître :

* évolution économique ;  
* opinion locale ;  
* acteurs concernés ;  
* médias locaux ;  
* mouvements ;  
* opportunités.

Si le joueur prépare une réforme, le jeu peut mettre en avant :

* soutiens ;  
* opposants ;  
* institutions ;  
* groupes concernés ;  
* conséquences possibles.

Cette logique est précisément ce que la refonte du Portal de FM26 cherche à accomplir : faire remonter davantage de données contextuelles au bon moment sans supprimer la profondeur disponible derrière.

---

# **13\. L’interface devrait avoir trois couches**

## **Couche 1 — Le monde**

Ce qui se passe.

Articles.

Événements.

Messages.

Statistiques.

Alertes.

## **Couche 2 — L’analyse**

Pourquoi cela se produit.

Relations.

Tendances.

Rapports.

Données.

Hypothèses.

## **Couche 3 — L’action**

Ce que le joueur peut faire.

Contacter.

Recruter.

Négocier.

Organiser.

Décider.

Déléguer.

Cette séparation rend la complexité lisible.

---

# **14\. L’Inbox devient le centre nerveux**

L’Inbox ne doit pas être une simple boîte à notifications.

Elle doit être le **flux de conscience du joueur**.

Elle lui dit :

« Voici ce qui vient d’arriver dans votre monde. »

Mais elle doit aussi distinguer :

### **Information**

« Une nouvelle enquête paraît. »

### **Opportunité**

« Une personnalité cherche une nouvelle organisation. »

### **Problème**

« Votre implantation baisse dans trois territoires. »

### **Décision**

« Votre conseiller demande une orientation. »

### **Alerte**

« Une coalition commence à se former contre votre réforme. »

### **Curiosité**

« Un petit mouvement local connaît une croissance inhabituelle. »

Cette dernière catégorie est importante.

Le jeu doit parfois attirer le joueur vers quelque chose qui **n’est pas encore important**.

---

# **15\. Le joueur doit pouvoir ignorer**

Tout ne doit pas être obligatoire.

Si le joueur reçoit 30 informations et doit traiter les 30, il devient secrétaire d’une interface.

Il doit pouvoir dire :

ignorer.

déléguer.

surveiller.

plus tard.

ne plus me notifier.

La capacité à **ne pas agir** fait partie du management.

---

# **16\. Les signaux faibles**

C’est une mécanique particulièrement intéressante pour un jeu politique.

Le système peut détecter :

« Une petite baisse de confiance apparaît dans ce groupe. »

Ce n’est pas encore une crise.

Mais le joueur peut enquêter.

Ou ignorer.

Plus tard :

la tendance devient importante.

Le joueur peut alors se dire :

« J’avais vu le signal il y a deux ans. »

Cela donne une profondeur temporelle extraordinaire.

---

# **17\. Les indicateurs ne doivent pas être des prédictions**

Il faut éviter :

« Risque de crise : 83 %. »

Ce genre d’indicateur peut rendre le système artificiellement transparent.

Il vaut mieux parfois donner :

* tendances ;  
* signaux ;  
* avis d’experts ;  
* données contradictoires ;  
* alertes.

Le joueur doit interpréter.

---

# **18\. L’incertitude doit être jouable**

Le joueur peut demander :

« Quelle est la situation ? »

Son équipe répond :

« Nous pensons que le soutien est en baisse, mais les données sont contradictoires. »

Il peut :

* agir immédiatement ;  
* demander davantage d’informations ;  
* attendre ;  
* envoyer quelqu’un enquêter.

L’information devient ainsi une ressource.

---

# **19\. Le système de réputation doit être multidimensionnel**

Il ne devrait pas exister une seule :

réputation \= 75\.

Un personnage peut avoir :

* réputation médiatique ;  
* réputation politique ;  
* réputation professionnelle ;  
* réputation locale ;  
* réputation nationale ;  
* réputation auprès de certaines catégories ;  
* crédibilité ;  
* fiabilité ;  
* compétence perçue.

Cela permet des profils beaucoup plus intéressants.

Quelqu’un peut être :

extrêmement respecté chez les experts, mais très impopulaire auprès du grand public.

Ou :

très populaire mais considéré comme peu fiable par ses partenaires.

---

# **20\. Les relations doivent être asymétriques**

A aime B.

Cela ne signifie pas nécessairement :

B aime A.

Un personnage peut considérer le joueur :

* comme un allié ;  
* tandis que le joueur le considère comme un outil.

Ou :

* comme un ami ;  
* tandis que l’autre le considère comme un rival.

Les relations doivent donc avoir une perception des deux côtés.

---

# **21\. La mémoire des personnages**

C’est une idée de design directement inspirée par la puissance des systèmes de personnages de *Crusader Kings III*.

Dans CK3, les personnages ont des traits, des choix et une histoire relationnelle qui influencent leur comportement, tandis que les systèmes de mémoire et d’inimitié donnent une continuité aux relations.

Dans le jeu politique :

**les personnages doivent se souvenir.**

Pas de tout.

Mais des choses importantes.

Un personnage peut se souvenir :

* que le joueur l’a soutenu ;  
* qu’il l’a abandonné ;  
* qu’il l’a promu ;  
* qu’il a recruté son rival ;  
* qu’il a refusé son aide ;  
* qu’il lui a fait perdre une élection ;  
* qu’il a tenu une promesse ;  
* qu’il l’a humilié publiquement.

Cette mémoire influence les interactions futures.

---

# **22\. Les relations doivent avoir une histoire**

Le joueur ne devrait pas voir seulement :

Relation : \+67.

Il devrait pouvoir voir :

2027 — première rencontre  
 2028 — recrutement  
 2029 — désaccord  
 2030 — soutien lors d’une crise  
 2031 — conflit sur une nomination

La relation devient une histoire.

---

# **23\. Le système de personnalité doit rester subtil**

Il ne faut pas avoir :

Personnalité : « Traître ».

Ce serait trop mécanique.

Il faut plutôt avoir des tendances :

* ambition ;  
* prudence ;  
* loyauté ;  
* opportunisme ;  
* idéalisme ;  
* goût du conflit ;  
* patience ;  
* besoin de reconnaissance ;  
* aversion au risque ;  
* etc.

Puis le comportement émerge.

Un personnage ambitieux et loyal peut rester fidèle très longtemps.

Un personnage ambitieux et opportuniste peut partir dès qu’une meilleure opportunité apparaît.

---

# **24\. Les personnalités doivent interagir avec les systèmes**

Une même proposition ne doit pas avoir la même réception auprès de tout le monde.

Une personne prudente peut préférer une stratégie progressive.

Une personne ambitieuse peut vouloir accélérer.

Une personne idéologique peut refuser un compromis.

Une personne opportuniste peut accepter si cela augmente sa carrière.

La personnalité devient donc une véritable mécanique.

---

# **25\. Le recrutement doit être une enquête**

Le recrutement politique devrait être beaucoup plus profond que :

chercher → cliquer → embaucher.

Le joueur peut avoir une **mission de recrutement** :

« Trouvez-moi quelqu’un capable d’organiser notre implantation dans cette région. »

Le staff cherche.

Il trouve plusieurs candidats.

Mais les rapports peuvent être incomplets.

Le joueur peut ensuite :

* rencontrer ;  
* vérifier ;  
* demander des références ;  
* parler à des personnes qui le connaissent ;  
* observer son comportement ;  
* négocier.

Cela donne une vraie sensation de management.

FM26 pousse déjà son recrutement vers des outils de recherche et de recommandations plus contextuels, avec des rapports du staff qui évaluent notamment l’adéquation d’un profil aux besoins du club.

---

# **26\. Le concept de « fit »**

Un personnage n’est jamais simplement :

bon.

Il est :

bon **pour quelque chose**.

Un excellent communicant peut être mauvais gestionnaire.

Un grand organisateur peut être politiquement incompatible avec le mouvement.

Un intellectuel brillant peut être incapable de gérer une équipe.

Un politicien populaire peut être mauvais négociateur.

Le recrutement devient donc un problème d’adéquation.

---

# **27\. Les rôles doivent être contextuels**

Il ne devrait pas exister une hiérarchie absolue des personnages.

Un acteur médiocre dans une fonction peut être excellent dans une autre.

Cela crée des découvertes.

Le joueur peut avoir :

« Ce type n’avait presque aucune réputation, mais il s’est révélé exceptionnel pour structurer nos réseaux locaux. »

Ce sont exactement ces histoires-là qui doivent apparaître.

---

# **28\. Le staff devient progressivement une machine de connaissance**

Plus le joueur grandit, plus il dispose de spécialistes.

Il ne devient donc pas seulement plus puissant.

Il devient **mieux informé**.

Cela permet une progression très intéressante :

### **Début**

« Je connais trois personnes. »

### **Milieu**

« J’ai un réseau. »

### **Haut niveau**

« J’ai des équipes qui surveillent le pays. »

Mais même là, les informations peuvent rester imparfaites.

---

# **29\. La délégation doit être intelligente**

Le joueur peut définir des consignes :

« Trouvez-moi des candidats correspondant à X. »

« Surveillez cette région. »

« Priorisez les profils ayant telle compétence. »

« Ne dépensez pas plus de telle somme. »

Le staff travaille ensuite.

Le joueur ne clique donc pas sur chaque détail.

---

# **30\. Mais le joueur doit pouvoir reprendre le contrôle**

À tout moment :

« Je veux gérer ça personnellement. »

C’est important.

Le jeu doit être profond pour le joueur qui adore micro-manager, mais viable pour celui qui préfère déléguer.

C’est encore une caractéristique fondamentale d’un bon jeu de management.

---

# **31\. La profondeur doit être optionnelle, mais jamais inaccessible**

Un joueur débutant peut simplement voir :

« Votre popularité baisse. »

Un joueur expérimenté peut ouvrir :

territoires → groupes → médias → relations → causes possibles.

Les deux jouent au même jeu.

Le second va beaucoup plus loin.

C’est une excellente manière de gérer la complexité.

---

# **32\. Le principe « easy to read, deep to inspect »**

C’est probablement l’une des meilleures règles de design du projet.

À première vue :

simple.

En profondeur :

immense.

Une fiche personnage peut commencer par :

**Claire Martin — journaliste — Paris**

Puis :

* réputation ;  
* audience ;  
* relations ;  
* carrière ;  
* articles ;  
* organisations ;  
* historique.

Puis chaque élément est cliquable.

---

# **33\. Les cartes doivent devenir le langage visuel du jeu**

Plutôt que des écrans saturés, utiliser :

* cartes ;  
* panneaux ;  
* dossiers ;  
* fiches ;  
* graphes ;  
* timelines ;  
* portraits ;  
* cartes géographiques.

Une carte \= une information.

Un clic \= davantage de contexte.

---

# **34\. La carte relationnelle**

Une vue graphique pourrait afficher :

joueur

au centre.

Puis :

* alliés ;  
* collaborateurs ;  
* journalistes ;  
* élus ;  
* organisations.

Avec des liens.

Mais cette vue ne doit pas être purement décorative.

Elle doit être navigable.

Cliquer sur une personne :

→ fiche.

Cliquer sur une relation :

→ histoire.

Cliquer sur l’organisation :

→ organisation.

Cela transforme le réseau en outil de gameplay.

---

# **35\. La chronologie personnelle**

Chaque personnage important doit pouvoir avoir une timeline.

Par exemple :

2026 : journaliste local  
 2028 : première enquête nationale  
 2030 : rejoint une rédaction nationale  
 2032 : conflit avec son directeur  
 2033 : création d’un média indépendant

Le joueur peut découvrir ces trajectoires.

---

# **36\. Les organisations doivent aussi avoir une mémoire**

Une organisation peut avoir une histoire :

fondation → croissance → crise → scission → fusion → transformation.

Ainsi, les organisations deviennent presque des personnages.

---

# **37\. Les organisations doivent pouvoir survivre aux personnages**

C’est très important.

Si le joueur quitte une organisation qu’il a créée, celle-ci peut continuer.

Elle peut :

* changer de direction ;  
* changer d’idéologie ;  
* s’allier ;  
* se diviser ;  
* prospérer ;  
* disparaître.

Le monde garde une mémoire de ce que le joueur a créé.

---

# **38\. Les idées doivent circuler**

Une idée ne doit pas être attachée à un seul acteur.

Une proposition peut :

* être créée par un groupe ;  
* reprise par un média ;  
* popularisée par un influenceur ;  
* récupérée par un parti ;  
* combattue par une organisation ;  
* devenir une loi.

Le jeu doit permettre cette circulation.

---

# **39\. L’équivalent politique du marché des transferts**

Football Manager possède un marché où les besoins des clubs rencontrent les profils des joueurs.

Le jeu politique pourrait avoir plusieurs « marchés » informels :

### **Marché des talents**

Personnes disponibles.

### **Marché des alliances**

Organisations cherchant des partenaires.

### **Marché des idées**

Idées cherchant des porteurs politiques.

### **Marché médiatique**

Journalistes, médias, audiences.

### **Marché des ressources**

Financements, soutiens, réseaux.

Ces marchés ne doivent pas nécessairement être littéraux.

Ils peuvent émerger du monde.

---

# **40\. Les opportunités**

Une excellente mécanique de FM à transposer est la notion d’opportunité.

Le joueur ne doit pas seulement avoir des tâches.

Il doit voir apparaître :

« Opportunity detected. »

Par exemple :

une organisation locale cherche un partenaire.

un élu cherche un successeur.

un média veut lancer une nouvelle émission.

une personnalité cherche une nouvelle structure.

un parti traverse une crise interne.

un mouvement connaît une croissance inattendue.

une coalition cherche un nouveau membre.

Le joueur décide s’il saisit l’opportunité.

---

# **41\. Les opportunités doivent avoir une fenêtre temporelle**

Une opportunité peut disparaître.

Si le joueur attend :

quelqu’un d’autre la saisit.

Cela donne au temps une véritable valeur.

---

# **42\. Les crises sont des opportunités ambiguës**

Une crise doit pouvoir être :

* un danger ;  
* une opportunité ;  
* les deux simultanément.

Le joueur peut penser :

« Cette crise nous détruit. »

Mais un autre acteur peut voir :

« C’est notre moment. »

Cela crée de la politique émergente.

---

# **43\. Les réformes comme projets**

Une réforme ne devrait pas être instantanée.

Elle peut avoir :

* préparation ;  
* négociation ;  
* opposition ;  
* mobilisation ;  
* vote ;  
* implémentation ;  
* conséquences.

Le joueur peut intervenir à différentes étapes.

---

# **44\. Les projets doivent avoir plusieurs chemins**

Une réforme peut être :

* négociée ;  
* accélérée ;  
* modifiée ;  
* reportée ;  
* abandonnée ;  
* remplacée par une autre.

Le joueur n’est donc pas confronté à un simple :

oui/non.

---

# **45\. Les lois doivent entrer en conflit**

Deux politiques peuvent être compatibles.

D’autres peuvent créer des tensions.

Une réforme peut :

* augmenter une ressource ;  
* mais réduire une autre ;  
* satisfaire un groupe ;  
* en mécontenter un autre.

Le joueur doit gérer des arbitrages.

---

# **46\. Les conséquences doivent être visibles progressivement**

Une politique publique ne devrait pas forcément afficher :

\+8 économie.

Il faut parfois :

premières conséquences après 3 mois.

Puis :

effets sociaux après 2 ans.

Puis :

conséquences politiques après 4 ans.

Cela donne de la profondeur temporelle.

---

# **47\. Le joueur doit pouvoir se tromper**

Et surtout :

**le jeu ne doit pas corriger immédiatement le joueur.**

Une mauvaise décision peut sembler bonne pendant longtemps.

Une bonne décision peut sembler mauvaise au départ.

Le joueur doit apprendre à penser en systèmes.

---

# **48\. Les informations du staff peuvent être divergentes**

Un conseiller économique peut dire :

« Cette réforme est risquée. »

Un conseiller politique :

« Politiquement, c’est probablement nécessaire. »

Un conseiller électoral :

« Notre base va mal réagir. »

Le joueur tranche.

Cela donne de la personnalité au staff.

---

# **49\. Les personnages doivent parfois avoir raison pour de mauvaises raisons**

Un conseiller peut proposer une bonne décision parce qu’il a intérêt à ce qu’elle réussisse.

Un autre peut donner un mauvais conseil sincère.

Un troisième peut avoir raison mais sur la base d’une mauvaise analyse.

Le joueur ne doit donc pas pouvoir simplement :

regarder le meilleur conseiller.

---

# **50\. Le jeu doit favoriser l’expérimentation**

Le joueur doit pouvoir tester une idée.

Pas parce qu’il sait qu’elle est optimale.

Mais parce qu’il veut savoir :

« Qu’est-ce qui se passe si je fais ça ? »

Cette curiosité est au cœur du projet.

---

# **51\. Le joueur doit avoir plusieurs niveaux de contrôle**

### **Niveau 1 — Personnel**

Je parle moi-même à quelqu’un.

### **Niveau 2 — Équipe**

Je demande à mon conseiller de s’en charger.

### **Niveau 3 — Organisation**

Je donne une directive générale.

### **Niveau 4 — Système**

Je change une règle ou une institution.

La même intention peut donc être poursuivie à différentes échelles.

---

# **52\. C’est là que le jeu devient vraiment « politique »**

Le joueur ne se contente pas d’avoir des pouvoirs.

Il doit décider **à quel niveau intervenir**.

Parfois :

convaincre une personne.

Parfois :

changer une organisation.

Parfois :

changer une règle.

Parfois :

laisser la société évoluer.

La meilleure décision n’est pas toujours la plus directe.

---

# **53\. Le pouvoir doit être distribué**

Le joueur ne doit jamais avoir un bouton :

« contrôler les médias ».

Il doit plutôt chercher à comprendre :

* qui possède quoi ;  
* qui influence qui ;  
* quelles institutions peuvent bloquer ;  
* quels réseaux existent ;  
* quelles ressources sont nécessaires.

Le pouvoir devient donc un problème de structure.

---

# **54\. Le joueur peut construire des institutions**

À un niveau très avancé, le joueur pourrait créer ou transformer :

* organisations ;  
* administrations ;  
* médias ;  
* partis ;  
* structures politiques ;  
* institutions.

Mais chaque nouvelle structure crée aussi :

* des responsables ;  
* des intérêts ;  
* des dépendances ;  
* des risques.

Le joueur construit donc des systèmes qu’il devra ensuite gérer.

---

# **55\. Le paradoxe du contrôle**

Plus le joueur construit, plus il crée de choses qui peuvent lui échapper.

C’est une mécanique extrêmement importante.

**Le pouvoir produit de la complexité.**

---

# **56\. Le jeu doit avoir des « histoires personnelles » et des « histoires systémiques »**

### **Histoire personnelle**

Moi \+ cette personne \+ notre relation.

### **Histoire organisationnelle**

Mon mouvement.

### **Histoire institutionnelle**

Notre réforme.

### **Histoire nationale**

Transformation de la France.

### **Histoire internationale**

Relations avec d’autres États.

Toutes ces histoires doivent se croiser.

---

# **57\. Une partie doit pouvoir être racontée à plusieurs échelles**

À la fin :

« Voici l’histoire de votre personnage. »

Mais aussi :

« Voici l’histoire de votre mouvement. »

« Voici l’histoire politique du pays. »

« Voici les grandes transformations économiques. »

« Voici les principales crises. »

Le joueur peut donc reconstruire son propre récit.

---

# **58\. La génération narrative vient après la simulation**

C’est fondamental.

Le moteur produit :

événements.

Puis le système narratif produit :

articles / messages / rapports / chronologies.

Il ne faut jamais faire l’inverse.

---

# **59\. Le jeu doit parfois être silencieux**

Toutes les journées ne doivent pas être passionnantes.

Il faut des périodes où :

rien d’important ne se passe.

Le joueur peut alors :

* analyser ;  
* recruter ;  
* préparer ;  
* observer ;  
* organiser.

Puis une crise survient.

Le contraste rend les événements importants.

---

# **60\. Le rythme doit être organique**

Le jeu doit alterner :

calme → activité → opportunité → tension → crise → conséquences → reconstruction → calme.

Pas :

événement spectaculaire toutes les 30 secondes.

---

# **61\. Le temps doit devenir un adversaire**

Certaines choses nécessitent du temps.

Une organisation prend des années.

Une réputation prend du temps.

Une réforme peut prendre du temps.

Une coalition peut mettre du temps à se construire.

Mais une crise peut surgir très vite.

Le joueur doit donc arbitrer :

agir maintenant ou construire pour plus tard ?

---

# **62\. Le jeu doit distinguer vitesse et profondeur**

Certaines actions sont rapides mais superficielles.

D’autres sont lentes mais structurantes.

Cela crée un choix stratégique.

---

# **63\. Le monde doit posséder une inertie**

Si le joueur change brusquement de stratégie, le monde ne doit pas changer instantanément.

Les personnes ont des habitudes.

Les organisations ont des cultures.

Les populations ont des opinions.

Les institutions ont des procédures.

L’inertie donne du réalisme.

---

# **64\. Mais il doit exister des points de bascule**

L’inertie ne doit pas signifier immobilité.

Certains systèmes peuvent atteindre des seuils.

Une tendance devient mouvement.

Une coalition devient parti.

Une crise devient rupture.

Une petite organisation devient nationale.

Le joueur doit pouvoir observer ces transitions.

---

# **65\. Le concept de « tipping point »**

Il peut exister des phénomènes où une accumulation progressive produit soudainement une transformation.

Mais le jeu doit éviter :

« variable \> 100 → événement automatique ».

Il faut plusieurs conditions.

Par exemple :

tension \+ réseau \+ événement déclencheur \+ capacité organisationnelle.

Le système produit alors une transition.

---

# **66\. La politique doit être un système de contraintes**

Le joueur doit constamment rencontrer :

* ressources limitées ;  
* temps limité ;  
* informations incomplètes ;  
* opposition ;  
* rivalités ;  
* règles ;  
* institutions ;  
* contraintes économiques ;  
* réactions sociales.

La liberté du joueur vient de la diversité des moyens disponibles pour contourner ou gérer ces contraintes.

---

# **67\. Il ne doit pas exister de « meilleure stratégie universelle »**

C’est essentiel.

Si le joueur découvre :

« Cette stratégie gagne toujours »

le système est mort.

Une stratégie doit fonctionner dans certains contextes et échouer dans d’autres.

Les adversaires doivent également apprendre.

---

# **68\. Les adversaires doivent s’adapter**

Si une stratégie fonctionne plusieurs fois, les autres acteurs peuvent :

* l’identifier ;  
* s’y opposer ;  
* changer leur comportement ;  
* former une coalition ;  
* développer une contre-stratégie.

Le monde apprend.

---

# **69\. Le joueur doit donc lutter contre un système adaptatif**

Il ne joue pas contre une IA qui triche.

Il joue contre des acteurs dont les intérêts changent selon ses actions.

Cela produit un véritable jeu politique.

---

# **70\. La simulation doit rester lisible malgré sa complexité**

Il faut une règle de design :

**La simulation peut être extrêmement complexe derrière l’écran, mais le joueur doit toujours pouvoir comprendre pourquoi le jeu lui montre quelque chose.**

Chaque information doit avoir un contexte.

Pas :

« Popularité : 63.4 ».

Mais :

« Votre soutien progresse chez les indépendants urbains mais recule fortement chez les jeunes diplômés. »

Puis :

pourquoi ?

Puis :

données.

---

# **71\. Les chiffres doivent être des portes, pas des fins**

Un chiffre doit permettre d’enquêter.

Il ne doit pas simplement servir de score.

---

# **72\. Les graphiques doivent raconter des processus**

Au lieu de :

Popularité : 72\.

Afficher :

évolution sur 5 ans.

Puis :

événements ayant probablement contribué aux changements.

Puis :

différences territoriales.

Le joueur lit l’évolution.

---

# **73\. Le jeu doit permettre la causalité locale**

Lorsqu’un événement survient, le joueur doit pouvoir demander :

« Pourquoi ? »

Le jeu peut alors montrer les principaux facteurs.

Pas nécessairement la formule mathématique exacte.

Mais une reconstruction intelligible :

« La baisse semble principalement liée à A, B et C. »

Cela permet au joueur de comprendre le système sans exposer toutes les équations.

---

# **74\. Le jeu doit parfois dire « on ne sait pas »**

C’est important.

Si les données sont insuffisantes :

« Les analystes ne parviennent pas à déterminer la cause principale. »

C’est plus réaliste qu’un jeu qui connaît toujours la vérité.

---

# **75\. Le design sonore et visuel doit servir l’information**

Le jeu n’a pas besoin d’être spectaculaire graphiquement.

Son identité peut venir de :

* documents ;  
* cartes ;  
* photos ;  
* journaux ;  
* portraits ;  
* graphiques ;  
* interfaces ;  
* dossiers ;  
* notifications.

Une esthétique de **centre de commandement / salle d’analyse / dossier politique vivant** pourrait être particulièrement cohérente.

---

# **76\. Pas besoin de personnages 3D**

La décision initiale de ne pas représenter les humains physiquement est cohérente avec ce design.

Le personnage peut exister par :

* portrait ;  
* nom ;  
* profession ;  
* historique ;  
* relations ;  
* messages ;  
* articles ;  
* statistiques.

Cela permet de consacrer les ressources à la simulation.

---

# **77\. Le jeu doit donner une sensation de « dossier vivant »**

Chaque personnage, organisation ou institution devrait presque être un dossier que le joueur peut explorer.

Mais un dossier vivant :

il change pendant que le joueur le consulte.

---

# **78\. Le monde ne doit jamais être complètement connu**

Même après 100 heures, le joueur devrait pouvoir découvrir :

« Je ne savais même pas que cette organisation existait. »

C’est un signe positif.

---

# **79\. Les secrets doivent être émergents**

Il peut exister :

* informations cachées ;  
* alliances discrètes ;  
* conflits internes ;  
* ambitions ;  
* réseaux.

Mais ils ne doivent pas tous être des « secrets scénaristiques ».

Ils peuvent simplement être des informations que le joueur ne possède pas encore.

---

# **80\. La recherche devient un gameplay à part entière**

Le joueur peut passer une heure à :

chercher la bonne personne.

Une autre à :

comprendre une institution.

Une autre à :

préparer une réforme.

Une autre à :

analyser pourquoi une région change.

Le jeu ne doit pas considérer cela comme du temps perdu.

C’est le jeu.

---

# **81\. Le gameplay doit accepter les joueurs obsessionnels**

Certains joueurs voudront :

tout savoir.

Le jeu doit leur offrir une profondeur énorme.

Mais il ne doit pas obliger tout le monde à tout lire.

C’est exactement la logique :

**profondeur optionnelle, accessibilité obligatoire.**

---

# **82\. Le jeu doit accepter les joueurs intuitifs**

Un joueur peut aussi dire :

« Je vais faire confiance à cette personne. »

Il peut.

Mais le système peut lui répondre plus tard :

cette confiance était fondée ou non.

Le jeu respecte donc différentes manières de jouer.

---

# **83\. Le joueur doit développer son propre style de connaissance**

Certains joueurs vont :

* analyser les données ;  
* suivre les relations ;  
* suivre les personnes ;  
* écouter leur staff ;  
* observer les médias ;  
* suivre l’économie ;  
* se concentrer sur les territoires.

Aucun style ne doit être obligatoire.

---

# **84\. Le jeu comme « bac à sable politique »**

À terme, le joueur doit pouvoir jouer sans objectif imposé.

Il peut dire :

« Je vais créer un mouvement et voir ce qui arrive. »

Ou :

« Je vais devenir journaliste. »

Ou :

« Je vais essayer de prendre le contrôle d’un parti existant. »

Ou :

« Je vais rester maire toute ma carrière. »

Ou :

« Je vais construire une organisation sans jamais me présenter à une élection. »

Le système doit supporter ces trajectoires.

---

# **85\. Le rôle du joueur peut même changer**

Une carrière peut évoluer :

journaliste → conseiller → militant → élu → ministre.

Mais aussi :

entrepreneur → mécène → créateur de mouvement.

Ou :

universitaire → expert → conseiller → ministre.

Ou :

fonctionnaire → responsable administratif → acteur politique.

Le jeu ne doit pas imposer une seule progression.

---

# **86\. La progression doit venir de la capacité d’action**

Le joueur ne monte pas de :

niveau 12 → niveau 13\.

Il acquiert :

* réputation ;  
* ressources ;  
* compétences ;  
* relations ;  
* responsabilités ;  
* accès.

La progression est donc organique.

---

# **87\. Le monde doit reconnaître le joueur progressivement**

Au début :

personne ne connaît le joueur.

Puis :

quelques personnes le connaissent.

Puis :

certains médias le mentionnent.

Puis :

des organisations le sollicitent.

Puis :

ses décisions commencent à modifier le monde.

Cette progression est extrêmement satisfaisante.

---

# **88\. Le changement d’échelle doit être ressenti**

Une décision du joueur au début peut affecter :

cinq personnes.

Plus tard :

une organisation.

Puis :

une ville.

Puis :

une région.

Puis :

le pays.

Mais plus l’échelle augmente, plus les conséquences indirectes augmentent aussi.

---

# **89\. C’est là que le pouvoir devient intéressant**

Le jeu ne doit pas simplement donner :

plus de boutons.

Il doit donner :

**plus de leviers sur un monde plus complexe.**

---

# **90\. Le véritable gameplay émergent**

Au final, le joueur devrait pouvoir produire des situations que même les développeurs n’ont pas anticipées.

C’est le test ultime.

Si le développeur doit écrire :

« Si le joueur fait A+B+C, alors événement D »

pour chaque possibilité, le système n’est pas assez général.

Si le joueur fait :

A+B+C

et que le moteur produit quelque chose de cohérent grâce aux règles existantes, alors le système fonctionne.

---

# **91\. Le design doit donc être systémique avant d’être spectaculaire**

Le projet peut avoir une interface magnifique.

Des cartes magnifiques.

De beaux portraits.

Une présentation élégante.

Mais aucune de ces choses ne compensera un monde statique.

La priorité doit être :

**simulation → interactions → information → interface.**

Pas :

interface → contenu → simulation.

---

# **92\. Le cœur du jeu en une phrase**

**Le joueur ne choisit pas parmi toutes les histoires possibles : il possède les moyens d’essayer de provoquer la sienne dans un monde qui possède sa propre volonté.**

---

# **93\. Le cœur de la boucle**

La boucle fondamentale devrait être :

### **1\. Observer**

Que se passe-t-il ?

### **2\. Identifier**

Qu’est-ce qui est important ?

### **3\. Enquêter**

Pourquoi ?

### **4\. Imaginer**

Qu’est-ce que je pourrais faire ?

### **5\. Préparer**

Qui faut-il contacter ? Quelles ressources faut-il ?

### **6\. Agir**

Je fais quelque chose.

### **7\. Attendre**

Le monde réagit.

### **8\. Observer les conséquences**

Certaines immédiates.

D’autres différées.

### **9\. Réévaluer**

Qu’est-ce que cela change ?

### **10\. Recommencer.**

C’est le gameplay.

---

# **94\. Le principe « faire moins, mais que cela compte »**

Le joueur ne doit pas cliquer 500 fois par journée.

Une bonne décision doit pouvoir avoir une vraie importance.

Le jeu doit donc chercher à réduire les actions administratives inutiles.

Par exemple :

au lieu de cliquer individuellement sur 30 personnes :

créer une mission de recrutement.

Au lieu de surveiller manuellement 100 territoires :

créer un rapport territorial.

Au lieu de lire 200 informations :

filtrer par priorité.

Le management consiste précisément à construire des systèmes permettant de gérer la complexité.

---

# **95\. La complexité doit être comprimée par le management**

C’est une idée essentielle pour un Football Manager politique.

Au début :

le joueur fait.

À mesure qu’il grandit :

le joueur organise des gens qui font.

Puis :

le joueur organise des organisations qui font.

La profondeur augmente mais le nombre de clics ne doit pas exploser proportionnellement.

---

# **96\. Le joueur doit construire sa propre machine politique**

C’est peut-être la meilleure manière de penser la progression.

Au départ :

**toi.**

Puis :

**toi \+ quelques personnes.**

Puis :

**une équipe.**

Puis :

**une organisation.**

Puis :

**un réseau.**

Puis :

**un appareil politique.**

Puis :

**un pouvoir institutionnel.**

Mais cette machine possède une vie propre.

---

# **97\. Le risque de la bureaucratisation**

Il faut cependant éviter qu’au niveau élevé le jeu devienne :

« Votre organisation génère automatiquement 500 actions par mois. »

Il faut conserver des personnes et des problèmes concrets.

Le joueur doit pouvoir descendre du macro au micro lorsqu’une situation l’intéresse.

---

# **98\. Le joueur doit pouvoir zoomer sur un individu**

Même au sommet du pouvoir :

« Qui est ce nouveau conseiller ? »

Clic.

Et soudain :

carrière → relations → ambitions → historique.

Cette continuité entre micro et macro est une des grandes ambitions du projet.

---

# **99\. La société comme immense base de données vivante**

Le monde du jeu doit finalement ressembler à une gigantesque base de données dans laquelle :

* les données évoluent ;  
* les acteurs prennent des décisions ;  
* les relations changent ;  
* les organisations naissent et meurent ;  
* les institutions se transforment ;  
* les populations évoluent.

Mais le joueur ne doit pas avoir l’impression de consulter une base de données.

Il doit avoir l’impression :

**d’habiter un monde.**

---

# **100\. Le paradoxe recherché**

Le jeu doit être :

**énorme derrière**

mais

**simple devant.**

Le joueur voit :

« Une personne veut me rencontrer. »

Il clique.

Derrière cette phrase peuvent se trouver :

* une relation ;  
* une organisation ;  
* un conflit ;  
* une opportunité ;  
* une stratégie ;  
* une information ;  
* une conséquence potentielle.

Mais le joueur n’a pas besoin de voir les équations.

---

# **101\. La simulation doit produire de la curiosité**

Chaque système doit pouvoir créer des questions.

Pourquoi ?

Qui ?

Comment ?

Depuis quand ?

Qu’est-ce qui explique ça ?

Qu’est-ce qui arriverait si… ?

Le joueur doit continuellement vouloir cliquer.

Pas parce que le jeu le récompense artificiellement.

Parce que **le monde est intéressant**.

---

# **102\. Le design parfait serait presque celui d’un jeu d’enquête \+ management**

Le joueur est simultanément :

* manager ;  
* enquêteur ;  
* stratège ;  
* négociateur ;  
* organisateur ;  
* observateur.

Il ne possède jamais toute l’information.

Il doit construire les moyens de l’obtenir.

---

# **103\. Le rapport aux jeux de stratégie traditionnels**

Le jeu ne doit pas être simplement :

territoire → armée → ressources → victoire.

La politique n’est pas seulement un problème de ressources.

C’est un problème de :

* personnes ;  
* perceptions ;  
* institutions ;  
* relations ;  
* information ;  
* légitimité ;  
* organisation ;  
* temps.

C’est ce qui doit distinguer le projet.

---

# **104\. Le rapport à Victoria 3**

*Victoria 3* fournit une leçon importante : la société devient intéressante lorsqu’on ne réduit pas les populations à une seule opinion.

Paradox a notamment expliqué que les groupes d’intérêt sont liés à des intérêts sociaux plus larges, tandis que leurs dirigeants peuvent modifier leur expression politique ; les partis peuvent ensuite émerger de coalitions entre groupes.

Le projet peut pousser cette logique plus loin :

groupes sociaux → individus → organisations → coalitions → institutions → politique.

---

# **105\. Le rapport à Crusader Kings**

CK3 fournit une autre leçon :

**les personnages peuvent être des moteurs de simulation.**

Le jeu officiel met en avant un monde rempli de personnages, chacun avec ses traits, choix et relations, capables d’agir, de s’allier, de trahir ou d’influencer les autres.

Dans le projet politique, les personnages doivent jouer ce rôle.

---

# **106\. Le rapport à Democracy 4**

*Democracy 4* montre l’intérêt d’une architecture où les politiques sont des objets systémiques avec différents effets, coûts, niveaux et dépendances plutôt que de simples choix textuels. Sa documentation de modding expose explicitement une structure de données où les politiques possèdent des paramètres et des effets interconnectés.

Le projet doit reprendre cette logique, mais avec une profondeur beaucoup plus grande :

une politique n’est pas une décision.

C’est :

**un objet qui entre dans un réseau causal.**

---

# **107\. Le rapport à Suzerain**

Suzerain montre la puissance de la mise en scène des décisions politiques.

Mais son approche est davantage narrative.

Ici, la narration doit être **produite par la simulation**.

On inverse donc le rapport :

### **Suzerain**

histoire → choix → conséquences.

### **Projet**

système → actions → conséquences → histoire.

C’est une distinction fondamentale.

---

# **108\. Le rapport à Football Manager**

Football Manager reste le modèle central parce qu’il démontre qu’un jeu peut être :

* extrêmement complexe ;  
* rempli de données ;  
* rempli de personnages ;  
* rempli de décisions ;  
* rempli de systèmes ;  
* mais rester jouable.

FM26 insiste notamment sur la recherche, le recrutement, les recommandations du staff, les données contextuelles, le Portal et la navigation vers des niveaux de détail plus profonds.

Le jeu politique doit appliquer cette philosophie à la société.

---

# **109\. Une différence majeure avec Football Manager**

Dans FM, l’objet central est relativement bien défini :

le football.

Ici, l’objet central est :

**la société.**

Cela signifie que le nombre de systèmes potentiels est beaucoup plus vaste.

Il faudra donc une architecture particulièrement modulaire.

---

# **110\. La modularité comme principe de design**

Le jeu doit pouvoir ajouter :

un nouveau type d’organisation.

Sans réécrire tout le moteur.

Ajouter :

une nouvelle institution.

Sans réécrire les personnages.

Ajouter :

un nouveau mécanisme social.

Sans réécrire l’interface.

Ajouter :

un nouveau pays.

Sans casser la France.

Cela doit être pensé dès le départ.

---

# **111\. Les systèmes doivent être composables**

Par exemple :

**Personne**

peut appartenir à :

**Organisation**

qui possède :

**Relations**

avec :

**Institution**

qui influence :

**Politique**

qui affecte :

**Population**

qui réagit via :

**Médias**

qui modifie :

**Opinion**

qui influence :

**Élection**

qui change :

**Gouvernement**

etc.

Le système devient un graphe.

---

# **112\. Le jeu comme graphe vivant**

On peut presque considérer toute la simulation comme :

**un immense graphe d’entités et de relations qui évolue dans le temps.**

Les entités sont les nœuds.

Les relations sont les arêtes.

Les événements modifient le graphe.

Les décisions créent de nouveaux liens ou détruisent des liens.

Le joueur cherche les leviers importants.

---

# **113\. Le joueur doit apprendre à penser en réseau**

Au début :

« Je veux convaincre cette personne. »

Plus tard :

« Je dois comprendre son réseau. »

Puis :

« Je dois comprendre l’organisation derrière elle. »

Puis :

« Je dois comprendre les intérêts derrière l’organisation. »

Le jeu fait progressivement évoluer la manière de penser du joueur.

---

# **114\. Le gameplay devient une recherche de leviers**

Le joueur ne demande plus :

« Quel bouton dois-je cliquer ? »

Il demande :

**« Où est le levier ? »**

C’est une philosophie beaucoup plus intéressante.

---

# **115\. Plusieurs leviers peuvent produire le même résultat**

Par exemple, pour obtenir une réforme, le joueur peut :

* convaincre ;  
* négocier ;  
* construire une coalition ;  
* gagner une élection ;  
* modifier l’opinion ;  
* recruter certaines personnes ;  
* attendre qu’un contexte change ;  
* etc.

Il n’existe pas forcément un chemin unique.

---

# **116\. Plusieurs résultats peuvent découler du même levier**

Convaincre quelqu’un peut :

* produire un allié ;  
* créer un conflit avec quelqu’un d’autre ;  
* modifier une coalition ;  
* changer une élection ;  
* déclencher une réaction médiatique.

Le monde est donc non linéaire.

---

# **117\. Les interactions doivent être réutilisables à toutes les échelles**

Le même moteur « relation » peut fonctionner entre :

* deux personnes ;  
* une personne et une organisation ;  
* deux organisations ;  
* une organisation et une institution ;  
* deux institutions ;  
* un État et une organisation internationale.

C’est ce qui permet d’obtenir une grande profondeur avec relativement peu de primitives.

---

# **118\. La règle de design la plus importante**

**Ne jamais créer une mécanique spéciale lorsqu’une mécanique générale peut produire le même phénomène.**

C’est probablement la règle que Claude Code devrait avoir en permanence en tête.

---

# **119\. La vidéo « Comment devenir dictateur » devient alors un stress test**

Le contenu de la vidéo peut servir à tester la richesse du moteur.

On peut prendre chacun de ses mécanismes et demander :

« Est-ce que notre simulation permet à ce phénomène d’émerger ? »

Mais aussi :

« Est-ce que le système permet les phénomènes inverses ? »

Par exemple :

* résistance institutionnelle ;  
* mobilisation démocratique ;  
* contre-mobilisation ;  
* pluralisme ;  
* changement d’opinion ;  
* fragmentation d’un mouvement ;  
* échec d’une stratégie.

La simulation doit pouvoir produire plusieurs directions.

---

# **120\. Le jeu ne doit donc pas être « le simulateur du dictateur »**

Il doit être :

**un simulateur politique général dans lequel la trajectoire autoritaire est l’une des nombreuses trajectoires émergentes possibles.**

Cela est beaucoup plus riche mécaniquement.

---

# **121\. Le joueur doit pouvoir créer une trajectoire totalement inattendue**

Le système pourrait produire :

* démocratisation ;  
* centralisation ;  
* fragmentation ;  
* coalition ;  
* crise ;  
* réforme ;  
* alternance ;  
* stabilité ;  
* instabilité ;  
* transformation institutionnelle ;  
* etc.

Le joueur peut tenter de pousser le système dans une direction.

Mais il ne contrôle jamais complètement la réponse du monde.

---

# **122\. Le vrai « endgame »**

Il ne devrait pas simplement y avoir :

« Vous êtes président, victoire. »

Atteindre le sommet ouvre au contraire une nouvelle phase.

Maintenant :

**comment maintenir une coalition ?**

**comment gouverner ?**

**comment faire fonctionner l’État ?**

**comment gérer les institutions ?**

**comment gérer les crises ?**

**comment gérer les personnes que vous avez nommées ?**

Le sommet du pouvoir devient donc le début d’un autre gameplay.

---

# **123\. Le véritable plaisir de fin de partie**

À très haut niveau, le joueur doit pouvoir regarder le monde et constater :

« J’ai créé ça. »

Mais aussi :

« Je ne contrôle plus tout ce que j’ai créé. »

C’est une sensation particulièrement forte pour un jeu de simulation.

---

# **124\. La philosophie de progression**

La progression ne doit donc pas être :

plus de statistiques.

Elle doit être :

**plus d’échelle \+ plus de leviers \+ plus de responsabilités \+ plus d’interdépendances.**

---

# **125\. Le principe de responsabilité**

Plus le joueur possède de pouvoir :

plus ses erreurs peuvent toucher de personnes.

Cela donne naturellement plus de poids aux décisions.

---

# **126\. Le joueur doit pouvoir revenir en arrière seulement dans certaines conditions**

Le jeu pourrait avoir :

* sauvegardes ;  
* différents modes ;  
* éventuellement ironman.

Mais le monde doit encourager à vivre avec les conséquences.

Une partie intéressante est une partie où le joueur pense :

« J’aurais dû faire autrement. »

Puis continue.

---

# **127\. Le jeu doit être capable de raconter l’échec**

Une partie où le joueur échoue peut être excellente si elle produit une histoire intéressante.

« J’ai presque réussi, puis cette coalition s’est formée contre moi. »

Le joueur veut alors recommencer.

---

# **128\. Le meilleur indicateur de réussite**

À terme, le joueur doit pouvoir raconter sa partie à quelqu’un :

« Mec, tu ne vas pas croire ce qui m’est arrivé. »

Et l’histoire ne vient pas d’un scénario écrit.

Elle vient du système.

C’est probablement **le test ultime du design**.

---

# **129\. La vision design condensée**

Le projet doit donc poursuivre simultanément six qualités :

### **Liberté**

Le joueur peut tenter énormément de choses.

### **Profondeur**

Chaque action s’insère dans plusieurs systèmes.

### **Lisibilité**

Le joueur n’est jamais obligé de comprendre toutes les couches simultanément.

### **Émergence**

Les histoires ne sont pas écrites à l’avance.

### **Personnalité**

Les personnages et organisations ont leurs propres intérêts.

### **Conséquence**

Les décisions changent réellement le monde.

---

# **130\. La formule finale**

Le jeu devrait donner cette sensation :

**Football Manager si, au lieu de gérer un club, on gérait progressivement une trajectoire de pouvoir dans une société entière.**

Mais même cette formulation est encore trop restrictive.

La véritable ambition est :

**Football Manager appliqué à l’ensemble de la vie politique et sociale.**

Un monde rempli de personnes.

Des personnes qui ont des ambitions.

Des ambitions qui produisent des organisations.

Des organisations qui forment des coalitions.

Des coalitions qui transforment les institutions.

Des institutions qui modifient la société.

Une société qui transforme les personnes.

Et au milieu de tout cela :

**le joueur.**

Pas comme le personnage principal d’une histoire écrite.

Mais comme **un acteur parmi tous les autres qui essaie de comprendre le système et d’y trouver sa place.**

---

# **131\. Le principe directeur à transmettre à Claude Code**

Si tout le document devait être résumé dans une seule instruction de design :

**Construis un monde politique, pas un jeu de décisions politiques.**

Puis :

**Construis les personnes, leurs intérêts, leurs relations, leurs organisations, leurs ressources, leurs informations, leurs institutions et leurs contraintes.**

Puis :

**Donne au joueur des moyens d’interagir avec eux.**

Puis :

**Laisse le monde réagir.**

Puis :

**Laisse le monde continuer sans lui.**

Puis :

**Laisse les conséquences s’accumuler.**

Puis :

**Transforme cette simulation en une histoire lisible pour le joueur.**

Le résultat recherché n’est pas :

« beaucoup de choix ».

C’est :

**beaucoup de choses que le joueur peut essayer.**

Et surtout :

**beaucoup de choses que personne n’avait explicitement écrites comme scénario.**

C’est cette différence qui doit faire du projet un véritable **Football Manager politique**.
